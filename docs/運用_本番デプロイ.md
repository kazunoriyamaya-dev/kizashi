# 運用 - 本番デプロイ手順

## 1. 全体フロー

```
feature/* → PR → Preview Deploy
             ↓
            Code Review
             ↓
            developブランチへ merge
             ↓
            staging で動作確認
             ↓
            main へ merge
             ↓
            Production Deploy (Vercel auto)
             ↓
            DB migration 反映 (Supabase auto / 手動)
             ↓
            動作確認
```

## 2. 初回本番セットアップ

### 2.1 Supabase Project 作成

1. Supabase Dashboard で新規プロジェクト
2. リージョン: `ap-northeast-1` (Tokyo)
3. Plan: Pro (PITR 必須)
4. `Database URL` / `API URL` / `anon` / `service_role` キーを控える

### 2.2 Migration 適用

```bash
supabase link --project-ref xxx
supabase db push
# または個別に:
psql "$DATABASE_URL" -f supabase/migrations/*.sql
psql "$DATABASE_URL" -f supabase/seed.sql # 本番では seed の admin 部分を除外推奨
```

### 2.3 Vercel Project 作成

1. GitHub リポジトリ連携
2. Framework: Next.js
3. Build Command: `pnpm build`
4. Output Directory: 自動検出
5. **Environment Variables を設定** (下記参照)

### 2.4 環境変数 (Production)

`.env.example` の全項目を Vercel Environment Variables に設定:

**重要 (機密度: 高)**:

- `SUPABASE_SERVICE_ROLE_KEY` — クライアントに絶対露出させない
- `STRIPE_SECRET_KEY` (`sk_live_...`)
- `STRIPE_WEBHOOK_SECRET` (`whsec_...`)
- `STRIPE_CONNECT_WEBHOOK_SECRET`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_MAPS_API_KEY`
- `LINE_CLIENT_SECRET`
- `LINE_CHANNEL_ACCESS_TOKEN`
- `LINE_CHANNEL_SECRET`
- `RESEND_API_KEY`
- `VAPID_PRIVATE_KEY`
- `ENCRYPTION_KEY` (`openssl rand -base64 32`)
- `CRON_SECRET` (`openssl rand -hex 32`)

**公開可 (機密度: 低)**:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` (`pk_live_...`)
- `NEXT_PUBLIC_VAPID_PUBLIC_KEY`
- `APP_URL` (`https://kizashi.example.com`)

### 2.4.A マーケティング自動化 (Phase 15) 用 環境変数 (オプション)

未設定の場合は該当機能が no-op (スキップ) となる。導入する施策のみ設定:

| カテゴリ       | 変数                                                          | 取得方法                        |
| -------------- | ------------------------------------------------------------- | ------------------------------- |
| X (Twitter)    | `TWITTER_BEARER_TOKEN`                                        | X Developer Portal              |
| Meta (FB/IG)   | `META_PAGE_ACCESS_TOKEN` / `META_PAGE_ID` / `META_IG_USER_ID` | Meta for Developers             |
| TikTok         | `TIKTOK_ACCESS_TOKEN`                                         | TikTok Content Posting API      |
| YouTube        | `YOUTUBE_ACCESS_TOKEN`                                        | Google Cloud → YouTube Data API |
| Meta Ads       | `META_AD_ACCESS_TOKEN` / `META_AD_ACCOUNT_ID`                 | Meta Marketing API              |
| Google Ads     | `GOOGLE_ADS_DEVELOPER_TOKEN` / `GOOGLE_ADS_CUSTOMER_ID`       | Google Ads API                  |
| TikTok Ads     | `TIKTOK_ADS_ACCESS_TOKEN`                                     | TikTok Ads API                  |
| アフィリエイト | `AFFILIATE_WEBHOOK_SECRET` (`openssl rand -hex 32`)           | 自社管理                        |

各 ASP からの postback URL は `https://kizashi.example.com/api/marketing/affiliate-webhook/<network>` で、Authorization Bearer に `AFFILIATE_WEBHOOK_SECRET` を設定してもらう。

### 2.5 Stripe 設定

1. Stripe Dashboard → Webhooks → エンドポイント追加
   - URL: `https://kizashi.example.com/api/stripe/webhook`
   - Events: `checkout.session.completed`, `payment_intent.succeeded`, `charge.refunded`
   - Signing secret を取得 → Vercel 環境変数に設定
2. Stripe Connect → Settings → Express 有効化
3. Connect 用 Webhook を別途設定 (任意)

### 2.6 Google OAuth 設定

1. Google Cloud Console → OAuth 2.0 Client
2. 承認済みリダイレクト URI:
   - `https://xxx.supabase.co/auth/v1/callback` (Supabase Google SSO)
   - `https://kizashi.example.com/api/instructor/google-calendar/callback` (Calendar 連携)
3. API ライブラリで有効化:
   - Calendar API
   - Routes API
   - Maps JavaScript API (将来用)

### 2.7 LINE Login 設定

1. LINE Developers Console → Channel 作成 (LINE Login)
2. Callback URL: `https://kizashi.example.com/api/auth/line/callback`
3. Channel Access Token + Secret を取得

### 2.8 Resend 設定

1. Resend Dashboard → ドメイン認証 (`kizashi.example.com`)
2. DNS に SPF / DKIM / DMARC を設定
3. API Key を取得

### 2.9 ドメイン

1. Vercel Project → Domains で本番ドメインを追加
2. DNS で CNAME を Vercel に向ける
3. SSL 自動発行を確認

## 3. 通常デプロイ

### 3.1 PR ベースのフロー

```bash
git checkout -b feat/new-feature
# 開発
git push origin feat/new-feature
# GitHub で PR 作成 → Vercel Preview URL 自動生成
# レビュー → develop に merge
# staging で確認 → main に merge → 本番デプロイ
```

### 3.2 DB migration を含む場合

1. PR に migration ファイルが含まれることを明示
2. **Preview Deploy では migration は実行されない** (リスク防止)
3. `staging` ブランチで `supabase db push --linked` を実行
4. 動作確認後、`main` に merge → 本番 Supabase に `supabase db push`

### 3.3 デプロイ前チェックリスト (pre-deploy)

- [ ] `pnpm lint` 通過
- [ ] `pnpm type-check` 通過
- [ ] `pnpm test` 通過
- [ ] PR レビュー approve
- [ ] DB migration を含む場合: down migration の検討
- [ ] 関係者 (KUGEDOU 山谷氏) への事前共有

### 3.4 デプロイ後チェックリスト (post-deploy)

- [ ] Vercel ログでエラーがないか確認
- [ ] Supabase Database → Logs でエラーなし
- [ ] Stripe Webhook 受信ログ正常
- [ ] 主要画面の動作確認 (3 ロール各 1 画面)
- [ ] Sentry / 監視ツールにアラートなし (将来導入)

## 4. 緊急デプロイ (ホットフィックス)

1. main から `hotfix/xxx` ブランチを切る
2. 修正 → push
3. PR を作成して emergency ラベル付与
4. レビュー (1 名で可)
5. main に merge → 本番デプロイ
6. 関係者にポストモーテム共有

## 5. Vercel Cron の確認

設定後、Vercel Dashboard → Settings → Cron Jobs で:

- `dispatch-notifications`: 5 分毎
- `notify-ticket-expiring`: 09:00 JST
- `sweep-expired-tickets`: 01:00 JST
- `notify-reservation-reminder`: 10:00 JST
- `marketing-dispatch`: 10 分毎 (SNS 投稿 / LINE ブロードキャスト / ステップメール / LP/ブログ公開 / attribution 同期)
- `marketing-ad-sync`: 04:00 JST (前日の広告メトリクスを各 platform から取得)

各 Cron は Authorization Bearer $CRON_SECRET を自動付与する。

## 6. 本番アクセス制限

- Supabase: IP allowlist (任意)
- Vercel: 管理画面は Vercel Team Member のみ
- GitHub: main ブランチへの push は admin のみ
- Stripe: Restricted Key を本番用に使用（service_role 相当の権限制限）
