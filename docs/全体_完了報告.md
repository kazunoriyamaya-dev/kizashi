## 1. プロジェクト概要

小中学生向けパーソナルサービス「Kizashi」の予約管理システムを、要件定義書 (`Kizashi 予約管理システム 要件定義 設計書.xlsx` 13 シート + QA 回答 Q001–Q025) に基づき、Phase 0–14 の 15 段階で実装した。

### ロール

- **管理者 (admin)**: マスタ管理、講師招待、体験予約承認、メッセージ監査、精算確定
- **講師 (instructor)**: プロフィール、Google Calendar 連携、レッスン履歴、報酬閲覧
- **顧客 (customer)**: 子供登録、講師検索、予約、チケット購入、メッセージ

### 技術スタック

- **Next.js 14** (App Router) / **TypeScript** (strict mode)
- **Supabase** (PostgreSQL + Auth + Storage + RLS)
- **Stripe** (Checkout + Webhook + Connect Express)
- **Google APIs** (OAuth + Calendar + Routes API)
- **LINE** (LINE Login + Messaging API)
- **Resend** (Email)
- **Web Push** (VAPID + Service Worker)
- **Vercel** (ホスティング + Cron)

## 5. セキュリティ・運用方針 (確定版)

### 多層防御

1. **DB レイヤー**: 全テーブル RLS 有効 + `revoke from public` + CHECK 制約
2. **アプリレイヤー**: `getCurrentUser()` でロール検証 + Zod バリデーション
3. **ミドルウェア**: route group ごとに role guard
4. **Webhook**: 署名検証 + 冪等性 (`event_id` UNIQUE)
5. **Cron**: `CRON_SECRET` Bearer 認証

### 機密データ保護

- OAuth refresh_token: AES-256-GCM 暗号化保存
- 顧客住所: AES-256-GCM 暗号化保存
- ログ: PII フィルタで自動マスク (`@/lib/logger`)
- `console.log` 禁止 (ESLint で警告)

### 不変監査ログ

- `audit_logs` は append-only (UPDATE/DELETE 拒否ポリシー)
- 全管理者操作・体験予約承認・精算確定・キャンセル・招待を記録
