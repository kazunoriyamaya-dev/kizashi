# 運用 - バックアップ / リストア

## 1. バックアップポリシー

| 対象 | 頻度 | 保存場所 | 保存期間 |
|---|---|---|---|
| Supabase DB (PITR) | 連続 | Supabase 管理 | 7日 (Free) / 14日 (Pro) |
| Supabase 日次フルバックアップ | 日次 | Supabase 管理 | 7日 |
| Supabase 手動 dump | 月次 | 別途 S3 / Google Drive | 12 ヶ月 |
| Stripe Connect Account 情報 | 自動 | Stripe Dashboard | 永続 |
| Google Calendar OAuth (encrypted) | DB バックアップに含む | Supabase | DB と同じ |

## 2. Supabase 標準バックアップ

Pro プラン以上で **PITR (Point-in-Time Recovery)** が有効。
- Supabase Dashboard → Database → Backups から確認
- 任意時点 (秒単位) への復旧が可能

## 3. 手動 pg_dump (月次)

```bash
# Supabase の DB 接続文字列を取得 (Project Settings → Database → Connection string)
export DATABASE_URL="postgresql://postgres:[YOUR-PASSWORD]@db.xxx.supabase.co:5432/postgres"

# スキーマ + データを dump (圧縮)
pg_dump "$DATABASE_URL" \
  --schema=public --schema=auth \
  --no-owner --no-privileges \
  -Fc -Z 9 \
  -f kizashi-backup-$(date +%Y%m%d).dump

# 暗号化して S3 等にアップロード
gpg --symmetric --output kizashi-backup-$(date +%Y%m%d).dump.gpg \
    kizashi-backup-$(date +%Y%m%d).dump
aws s3 cp kizashi-backup-$(date +%Y%m%d).dump.gpg s3://kizashi-backups/
```

## 4. リストア手順

### 4.1 PITR からの復元 (Supabase Dashboard)
1. Dashboard → Database → Backups
2. 復元したい日時を選択（秒単位）
3. 「Restore」ボタンを押下
4. **注意**: 既存 DB は新しいプロジェクトとして復元される
5. 復元先プロジェクトの URL / KEY を Vercel 環境変数に反映
6. アプリの動作確認

### 4.2 pg_dump からのリストア
```bash
# 復元先 DB を作成 (Supabase で新規 project)
export RESTORE_URL="postgresql://postgres:[NEW-PASSWORD]@db.yyy.supabase.co:5432/postgres"

# 復号
gpg --decrypt kizashi-backup-YYYYMMDD.dump.gpg > kizashi-backup-YYYYMMDD.dump

# リストア
pg_restore --dbname="$RESTORE_URL" \
  --no-owner --no-privileges \
  --clean --if-exists \
  --jobs 4 \
  kizashi-backup-YYYYMMDD.dump

# 動作確認
psql "$RESTORE_URL" -c "select count(*) from public.reservations;"
```

### 4.3 リストア後のチェックリスト
- [ ] テーブル件数が想定通り
- [ ] RLS が有効化されている (`select tablename, rowsecurity from pg_tables where schemaname='public';`)
- [ ] EXCLUDE 制約が存在 (`select conname from pg_constraint where contype='x';`)
- [ ] RPC 関数が存在 (`select proname from pg_proc where pronamespace='public'::regnamespace;`)
- [ ] Supabase Auth ユーザーがログイン可能
- [ ] Stripe 連携が動作 (テスト決済)
- [ ] Google Calendar 連携が動作 (refresh token decrypt 成功)

## 5. 災害復旧 (DR) 目標

- **RTO (Recovery Time Objective)**: 4 時間
- **RPO (Recovery Point Objective)**: 24 時間 (Free plan) / 5 分 (Pro plan PITR)

## 6. 月次リハーサル

- 毎月 1 営業日に**マスク済みデータ**でリストアテストを実施
- 個人情報のマスク手順: `docs/運用_データマスキング.md` (要作成)
- 結果を `audit_logs` に actor_role='admin' で記録

## 7. データ削除 / 退会対応 (Q020)

- 顧客の退会要求は admin が `profiles.status='deleted'` で論理削除
- メッセージは保持 (Q020)
- 個人情報削除依頼: GDPR / 個人情報保護法に従い、`customers` / `children` / `addresses` 関連を匿名化
- 削除/匿名化操作は必ず `audit_logs` に記録
